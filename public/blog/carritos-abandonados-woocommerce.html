Recuperar carritos abandonados en WooCommerce sin plugins de pago

Bastián Sandoval · Julio 2026 · Actualizado en octubre 2026 · WooCommerce, PHP

En una tienda de repuestos y maquinaria, el carrito abandonado es el pan de cada día: el cliente arma una lista, compara con la competencia y se va. Hay plugins de pago que resuelven esto con una suscripción mensual por tienda y, por debajo, casi todos hacen lo mismo. Para la tienda de Motormaq preferí escribir el módulo a medida dentro de un plugin propio: son unos cientos de líneas de PHP y toda la lógica queda en tus manos.

Esto es lo que hace, cómo está armado y qué le falta. Está escrito sobre el código real del plugin, no sobre una receta genérica.

El flujo completo en cuatro estados

Cada carrito vive como una fila de una tabla propia, wp_mv_carritos, y pasa por estos estados:

  • activo: el visitante tiene productos en el carrito.
  • enviado: pasaron las horas de espera y se le mandó el correo de recuperación.
  • recuperado: después del correo, el cliente terminó una compra.
  • error: el correo no pudo enviarse (wp_mail() devolvió false).

1. Capturar el carrito

El módulo escucha woocommerce_cart_updated. Cada vez que el carrito cambia, guarda su contenido como JSON (producto, variación, cantidad, nombre y precio con IVA), el total y la clave de sesión de WooCommerce. Si el carrito queda vacío, borra el registro activo de esa sesión: un carrito vacío no es un carrito abandonado.

Guardar nombres y precios tal como el cliente los vio, en vez de recalcularlos después, permite armar el correo sin cargar el carrito real y deja un registro de lo que había en él.

2. Conseguir el correo del visitante

Sin correo no hay a quién escribirle. Hay dos caminos:

  • Si el usuario tiene sesión, el correo y el nombre salen de su cuenta.
  • Si es invitado, un pequeño script escucha el campo de correo del checkout (el clásico #billing_email y el del checkout por bloques, #email) y lo envía por AJAX apenas el visitante sale del campo:
$(document).on('blur change', '#billing_email, #email, input[type="email"]', function () {
  window.setTimeout(capturarEmail, 200);
});
// capturarEmail() valida el formato y hace
// $.post(ajaxUrl, { action: 'mv_guardar_email', nonce, email, nombre })

Tiene que ser al salir del campo y no al enviar el pedido: quien abandona nunca llega a enviarlo. El endpoint verifica un nonce de WordPress y valida el correo con is_email() antes de guardarlo.

3. Cerrar el carrito cuando sí compran

Si el cliente compra, el registro deja de ser "abandonado". WooCommerce tiene dos checkouts y cada uno dispara un hook distinto, así que el módulo engancha los dos: woocommerce_checkout_order_processed (el clásico) y woocommerce_store_api_checkout_order_processed (el de bloques). Al cerrar:

  • si el correo todavía no se había enviado, el registro se elimina;
  • si ya se había enviado, pasa a recuperado y guarda el total del pedido.

El carrito se busca por la sesión o por el correo de facturación del pedido, lo que cubre al cliente que compra desde otro dispositivo.

4. Decidir cuándo un carrito está abandonado

Una tarea de WP-Cron corre cada hora y toma los carritos que cumplen tres condiciones: están activos, tienen correo y llevan más de N horas sin cambios (3 por defecto, configurable):

SELECT * FROM wp_mv_carritos
WHERE estado = 'activo' AND email <> '' AND actualizado < %s
LIMIT 20

El LIMIT 20 acota cada pasada a 20 correos como máximo, lo que evita ráfagas si de pronto hay muchos carritos pendientes. Los registros sin correo se limpian a los 15 días y todo lo demás a los 60.

5. El cupón

El correo puede incluir un cupón. El que usa el módulo es de un solo uso y vence a los pocos días:

$cupon = new WC_Coupon();
$cupon->set_code( 'VUELVE' . strtoupper( wp_generate_password( 6, false ) ) );
$cupon->set_discount_type( 'percent' );
$cupon->set_amount( $pct );        // 5 % por defecto
$cupon->set_usage_limit( 1 );      // un solo uso
$cupon->set_date_expires( time() + $dias * DAY_IN_SECONDS ); // 7 días por defecto
$cupon->save();

Una advertencia honesta: este cupón no está atado al correo del cliente. Quien reciba el código por un reenvío podría usarlo una vez. Si te preocupa que circule, el arreglo es una línea, $cupon->set_email_restrictions( array( $fila->email ) ), y es lo primero que le agregaría.

6. El correo y el enlace que restaura el carrito

Se manda un solo correo, sin secuencias: la tabla de productos con su subtotal, el cupón si está activado y un botón "Recuperar mi carrito". Ese botón apunta a la URL del carrito con un token aleatorio de 32 caracteres: ?mv_recuperar=….

Al abrirlo, el módulo busca el token, reconstruye el carrito y redirige con un aviso de confirmación. Tiene tres reglas que evitan problemas reales:

  • solo agrega lo que no está ya en el carrito, para no duplicar cantidades si el cliente vuelve a entrar;
  • omite los productos que ya no se pueden comprar o no tienen stock;
  • si el carrito ya figura como recuperado, no hace nada.

7. Medir sin engañarte

El panel del plugin muestra "carritos recuperados / correos enviados" y el monto recuperado. Ojo con lo que significa: un carrito se marca recuperado si, después de enviado el correo, aparece un pedido de la misma sesión o con el mismo correo, use o no el cupón. Parte de esas compras habría ocurrido igual. Es una cifra útil para ver la tendencia, no para atribuirle al correo todas esas ventas.

Cómo probarlo sin esperar horas

La espera mínima configurable es de una hora, así que para probar el flujo completo conviene adelantar el reloj a mano:

  1. Agrega un producto al carrito y escribe un correo tuyo en el checkout (sin enviar el pedido).
  2. En la tabla wp_mv_carritos, retrocede el campo actualizado de esa fila unas 5 horas.
  3. Fuerza la tarea con WP-CLI: wp cron event run mv_revisar_carritos.

Debería llegarte el correo y la fila pasar a enviado. Si completas la compra desde el enlace del correo, pasa a recuperado.

Lo que le falta

  • El cupón no está restringido por correo (ver arriba).
  • Es un solo correo; no hay un segundo recordatorio.
  • El correo no trae un enlace para darse de baja.
  • Los correos salen con wp_mail(): sin un SMTP configurado, por ejemplo con tu correo corporativo, muchos caen en spam.
  • Depende de WP-Cron, que se dispara con las visitas al sitio; en una tienda con poco tráfico conviene reemplazarlo por un cron real del servidor.

Lo que aprendí

  • La tabla propia (en vez de post meta) hace que las consultas del cron sean triviales y no ensucia la base de WordPress.
  • Hay que cerrar el carrito en los dos checkouts de WooCommerce; si solo cubres uno, le mandas recordatorios a gente que ya compró.
  • Capturar el correo al salir del campo, y no al enviar el pedido, es lo que hace que el módulo tenga a quién escribirle.
  • "Recuperados sobre enviados" es una métrica honesta solo si recuerdas que no distingue entre una venta recuperada y una que igual iba a ocurrir.
